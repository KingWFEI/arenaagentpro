# 整理房间混合智能体

本目录采用“本地结构化数据主导，视觉模型按需介入”的设计。

## 执行流程

1. 从 `movable_object_id` 建立目标清单。
2. 已知资产名先由本地规则识别；未知资产允许 VLM 写入开放式 `semantic_label`，但真正驱动执行的 `destination_type` 只允许 `sofa`、`dining_table`、`trash_bin`、`shoe_storage` 四类。
3. 角色在出生朝向保持不动，每次等待 0.75 秒后采集 RGB/分割拼图，最多尝试 10 次。
4. 右侧分割图非黑、不是 RGB 画面的延迟副本，且可见对象 ID 连续两帧一致时，才接受该帧。
5. 只保留这一张初始正向稳定帧，立即连同严格盘点提示词发送给关闭思考模式的 Kimi K2.6；启动盘点不做任何角度转向。
6. 快速视觉模型的单图标注写入持续世界模型，角色移动、抓取和放置后的新观察继续并入该模型。
7. 调度器根据目标位置、目的地距离、可见性和历史失败次数选择目标。
8. 抓取后使用 `get_object_in_hand` 验证，不能用动作返回值或截图代替。
9. 规划器根据目标与家具 AABB 计算落点；新版坐标直放不需要单独规划接近点或避障路线。
10. 四类目的地统一用 `put_down_sth_to_location` 的 `force_locate` 坐标落点；人物不需要先走到家具旁边。
11. 坐标放置不再回读 AABB 校验：`put_down_sth_to_location` 是把物品强制放到指定坐标，动作返回 success 即认为已经放好，目标立刻标记完成。省下的这一步在 400 秒里很值钱，也避免读到放置前的旧坐标而把放好的物品重新拿起来重放。
12. 912 客厅布局固定：首帧用 AABB 中心和尺寸将当局分割 ID 绑定到固定家具先验。主沙发、餐桌、垃圾桶不再依赖 VLM 标注；脚凳、茶几、电视柜、电视、落地灯和餐椅会被标成不可拾取家具。如果首帧漏掉某个目的地，仍可用其固定 AABB 规划 `put_down_sth_to_location` 落点。
13. 已持物、待放置链路始终优先，不会被其他未观察目标触发的 VLM 请求打断。
14. 单图盘点结果写入世界模型后，直接进入本地抓取和放置流程。
15. 对极小、紧凑、棕色不规则物体做严格的 AABB 纠偏，避免把核桃误分到垃圾桶；固定坐标已确认的电视柜等家具不能被模型重新登记成鞋柜。

## 性能策略

- 首帧完成目标和家具建图后不再枚举整幅可见物体；静态信息继续使用缓存，常规循环只刷新当前动作相关对象。
- 整理房间使用专用本地快速循环：题目、动作空间和任务响应只读取一次，连续执行各个物理子动作；只有最终 `submit_answer` 会提交。
- 路线规划从赛题服务下发的真实出生坐标开始，并穷举最多五件物品的剩余顺序，兼顾普通放置和直接精确放置后的角色位置。
- `config.toml` 中的 0.25 秒只作为物理动作等待上限；同步移动、抓取和冻结放置使用 0.02～0.05 秒的动作级等待。初始视角统一感知每次先等待 0.75 秒，再以对象 ID 集合连续两帧稳定为就绪条件。
- 统一感知不再使用固定对象数量门槛：对象较少但分割完整的鞋柜视角可以通过；人物先出现、其余物体随后补齐的过渡帧会继续等待。原地发现新对象不会重置补扫预算，只有人物真实移动后才能开启新的搜索轮次。
- 餐桌物品统一按桌面高度上方 2 厘米放置；抓取、放置各一步，中间只有一次手持确认，目标完成即切下一个。
- 启动时只有一次 Kimi 高速视觉模型单图盘点；之后只有本地异常恢复策略明确返回“需要 VLM”时才再发起请求。

## 模块职责

- `strategy.py`：流程编排和状态转换。
- `world_model.py`：跨视角世界状态。
- `scanner.py`：无可执行计划时的机会式视野探索。
- `scheduler.py`：目标顺序。
- `destinations.py`：开放语义标签的规范化，以及四类受限目的地映射。
- `planner.py`：移动和放置坐标。
- `geometry.py`：地板、障碍物和几何关系。
- `verifier.py`：抓取与放置验证。
- `recovery.py`：失败分类、计数和重试。
- `vlm_policy.py`：VLM 升级条件。
- `prompt.txt`：只在升级时发送给 VLM 的异常诊断提示。

## 关键日志

- `Using cached tidy-room fast loop`：已进入缓存题目和任务服务数据的连续本地执行模式。
- `Using local deterministic action without VLM call`：本步完全由本地策略执行。
- `Tidy-room local plan`：已生成目标、目的地、接近点和放置点。
- `Tidy-room placement done`：坐标放置动作成功，目标直接标记完成。
- `Tidy-room promoted geometric `：没有可信标注时按几何挑出来的目的地。
- `Skip arena update_action for intermediate tidy-room action`：已执行仿真动作，但跳过了不必要的赛题服务中间提交。
- `Tidy-room escalates to VLM because ...`：本地策略主动请求视觉模型。
