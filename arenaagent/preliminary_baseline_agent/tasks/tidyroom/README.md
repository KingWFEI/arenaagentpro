# 整理房间混合智能体

本目录采用“本地结构化数据主导，视觉模型按需介入”的设计。

## 执行流程

1. 从 `movable_object_id` 建立目标清单。
2. 已知资产名先由本地规则识别；未知资产允许 VLM 写入开放式 `semantic_label`，但真正驱动执行的 `destination_type` 只允许 `sofa`、`dining_table`、`trash_bin`、`shoe_storage` 四类。
3. 当前临时启用首帧加载诊断：角色保持不动，连续执行十轮“等待 0.25 秒、保存 RGB/分割拼图”，并记录每轮实际累计时间、可见对象数、成功分割标注数和原始分割区域数。十轮完成后，首帧仍不调用 VLM，只读取一次 TongSim 结构化可见物体。只要当前视野已有“可处理目标 + 对应家具”并能生成抓取计划，就立即规划搬运。
4. 首帧结构化结果为空，或没有形成可执行组合时，立即转向 45 度。转向后由快速循环等待 0.25 秒，让相机和分割缓冲稳定。
5. 第二帧直接进行一次完整同帧采集，把结构化信息、RGB 和分割 ID 图交给 VLM。第二帧 VLM 若建议转向，角度统一改写为扫描器的 45 度，保证扫描覆盖范围与计数一致。
6. 第三帧起恢复单次结构化感知；当前视野仍没有可执行组合就直接转向 45 度。每次转向后只等待 0.25 秒再感知，不对空结果进行原地二次读取。角色移动、抓取和放置后的新观察持续并入跨视角世界模型。
7. 调度器根据目标位置、目的地距离、可见性和历史失败次数选择目标。
8. 抓取后使用 `get_object_in_hand` 验证，不能用动作返回值或截图代替。
9. 规划器根据地板、障碍物和家具 AABB 计算接近点与放置点。
10. 垃圾先用 `move_to_object` 进入引擎认可的交互距离，再调用官方容器动作；首次找不到容器只向前微调 15 厘米，第二次仍失败就停止绕行并回退到桶内精确落点。桌面和沙发直接使用规划坐标精确放置。
11. 垃圾放入后等待一个本地循环让物理状态稳定，再刷新当前目标和目的地 AABB；几何校验通过才标记完成。
12. 已持物、待放置和待校验链路始终优先，不会被扫描或其他未观察目标触发的 VLM 请求打断。
13. 完成一圈机会式扫描后若仍缺目标或目的地，只再进行最多四次本地补充转向；仍无结果才懒加载截图并调用 VLM。
14. 连续两次几何失败会暂时延后该目标，并保留累计失败次数以轮换槽位和接近方向。

## 性能策略

- 首帧完成目标和家具建图后不再枚举整幅可见物体；静态信息继续使用缓存，常规循环只刷新当前动作相关对象。
- 整理房间使用专用本地快速循环：题目、动作空间和任务响应只读取一次，连续执行各个物理子动作；只有最终 `submit_answer` 会提交。
- 路线规划从赛题服务下发的真实出生坐标开始，并穷举最多五件物品的剩余顺序，兼顾普通放置和直接精确放置后的角色位置。
- `config.toml` 中的 0.25 秒只作为物理动作等待上限；同步移动、抓取和冻结放置使用 0.02～0.05 秒的动作级等待，但转向保留 0.25 秒让相机可见物体缓冲稳定。
- 首帧无组合时只转向；唯一固定的完整视觉诊断位于转向后的第二帧。其他扫描帧每个方向只读取一次结构化结果，不再因空结果原地重试。原地发现新对象不会重置补扫预算，只有人物真实移动后才能开启新的搜索轮次。
- 餐桌物品统一按桌面高度上方 2 厘米放置，快速路径失败状态持久化到目标；连续三次几何失败会停止重复抓放并提交真实完成度。
- 除第二帧固定的一次完整视觉诊断外，只有本地异常恢复策略明确返回“需要 VLM”时才获取 RGB/语义分割图并发起 API 请求；每次升级都会重采完整结构化信息，保证提示上下文和图像属于同一次采集。

## 模块职责

- `strategy.py`：流程编排和状态转换。
- `world_model.py`：跨视角世界状态。
- `scanner.py`：无可执行计划时的机会式视野探索。
- `scheduler.py`：目标顺序。
- `destinations.py`：开放语义标签的规范化，以及四类受限目的地映射。
- `planner.py`：移动和放置坐标。
- `geometry.py`：地板、障碍物和几何关系。
- `verifier.py`：抓取与放置验证。
- `recovery.py`：失败分类、计数和重试。
- `vlm_policy.py`：VLM 升级条件。
- `prompt.txt`：只在升级时发送给 VLM 的异常诊断提示。

## 关键日志

- `Using cached tidy-room fast loop`：已进入缓存题目和任务服务数据的连续本地执行模式。
- `Using local deterministic action without VLM call`：本步完全由本地策略执行。
- `Tidy-room local plan`：已生成目标、目的地、接近点和放置点。
- `Tidy-room placement verified`：几何校验成功。
- `Tidy-room placement invalid`：放置失败并生成了下一次重试方案。
- `Tidy-room defers repeatedly failed target`：该目标连续失败，暂时切换到其他物体。
- `Skip arena update_action for intermediate tidy-room action`：已执行仿真动作，但跳过了不必要的赛题服务中间提交。
- `Tidy-room escalates to VLM because ...`：本地策略主动请求视觉模型。
