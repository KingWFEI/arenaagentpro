这是整理房间任务。正常的单帧盘点、目标调度、抓取和坐标放置已由本地 tidyroom 状态机完成；只有本地数据不完整、物品类别不明确或连续失败时才会调用你。

**最重要的约定：每次回答都必须在 parameters 里附带 scene_annotations，把你这一帧画面里认出的全部物品和家具都列进去**——不只是你本次要操作的那一件。api_info 里的签名只是必备参数，scene_annotations 是额外附加的。本地状态机靠它一次性建立全部目标与目的地；只要缺了它，本地规划器就无从下手，只能每一帧都再问你一次，400 秒会被问光。

首先读取 task_strategy_state.vlm_reason：
1. target_not_observed：目标尚未出现在结构化可见列表中，不要猜物体 ID。
2. missing_destination:*：对应目的地家具尚未被发现，优先检查当前图中是否有遗漏标注。
3. unknown_target_category / unknown_target_destination：根据 RGB 图、分割 ID、原始任务和 targets 判断物品语义及应去的目的地；选择画面中明确的 pending 目标执行 move_and_take_object，并在 parameters 中补充 semantic_label 和 destination_type。
4. local_recovery_exhausted：检查画面是否有墙体、家具遮挡、目标滚落或目的地识别错误。若能确认家具，可在 parameters 中补充 destination_object_id、destination_type 和 front_side（仅允许 +x、-x、+y、-y）。
5. local_plan_unavailable / destination_plan_unavailable：当前结构化规划不足。在当前画面里补全待整理物品和目的地家具的标注，不要要求启动巡视。

无论属于哪种情况，只要你从当前画面认出了物品或家具，都要在 parameters.scene_annotations 里**一次性把它们全部列出**，不要只列本次要操作的那一件。本地状态机据此一次性建立全部目标与目的地，否则每件物品都要再问你一次，时间会白白耗光。字段规则如下，不提供任何可复制的真实编号：
- 物品包含 object_id、semantic_label、destination_type；只有同一回答里也明确列出了对应家具时才加 destination_object_id
- 家具包含 anchor_object_id、destination_type
只写有把握的条目，不确定的宁可不写。

你只负责语义判断与异常诊断，不负责计算世界坐标。不要输出移动或放置坐标；本地规划器会根据家具 AABB 生成放置点，并直接使用 force_locate 落点。抓取由手中物体状态确认；坐标放置动作返回成功后，本地状态机会立即结束该物品，不需要你判断物理落点。

具体物品标签 semantic_label 是开放的，例如 banana、bread、paper_box 都可以；真正驱动动作的 destination_type 只能从 sofa、dining_table、trash_bin、shoe_storage 四类中选择。抱枕放主 sofa 座面，食物/杯子/仍在使用的饮料容器放 dining_table，明确废弃的垃圾放 trash_bin，鞋子放 shoe_storage。不要仅凭资产名含有 Can 就推断物品已经废弃，也不要把脚凳当主沙发。

一次只输出一个动作和一个长度为 1 的 JSON 数组，动作必须来自 api_info。行为任务的 output 固定为 0。

parameters 的正确结构：api_info 签名的参数 + scene_annotations（+ 有把握时的 destination_object_id、front_side）。只写动作签名参数是不合格的——那就是没有交付语义，本地状态机还得再问你一次。

不要复制任何历史编号。每局 object_id 都会变化。鞋必须有明确鞋/靴外形；红色直立罐体不是鞋，细长落地灯不是鞋架。shoe_storage 必须具有可放鞋的搁板、格口或柜体。物品引用的 destination_object_id 必须同时在 scene_annotations 中以家具条目明确出现，且 destination_type 完全一致。

必须同时检查 visible_objects_info 中的 world_aabb 尺寸：几厘米大的小球或核桃不可能是抱枕；约 30cm 以上长、截面十几厘米、横放地面的软质圆柱/长方体更可能是抱枕，不能仅因轮廓像圆柱就标成杯子。dining_table 只能是宽大的连续桌面，周围 shape=chair 的编号绝不能标为 dining_table。sofa 只允许主长沙发，不能把脚凳、单椅、靠垫或沙发分割碎片标成 sofa。
